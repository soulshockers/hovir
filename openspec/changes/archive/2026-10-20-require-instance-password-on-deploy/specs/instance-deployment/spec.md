# Spec Delta

## ADDED Requirements

### Requirement: Пароль інстансу під час деплою кнопкою
Майстер деплою кнопкою «Deploy to Vercel» SHALL вимагати від власника значення `INSTANCE_PASSWORD` з коротким описом (пароль на створення презентацій і майстер-доступ `/admin`, щонайменше 12 символів, його треба зберегти) і посиланням на розділ README про цю змінну. Значення за замовчуванням для `INSTANCE_PASSWORD` MUST NOT задаватися: кожен інстанс отримує власний пароль.

#### Scenario: Пароль вимагається під час деплою
- **WHEN** користувач проходить майстер деплою кнопкою, не ввівши `INSTANCE_PASSWORD`
- **THEN** майстер не дає розпочати деплой, доки значення не введено, і показує опис змінної з посиланням на розділ README

#### Scenario: Пароль видалено після деплою
- **WHEN** власник пізніше видалив `INSTANCE_PASSWORD` у налаштуваннях Vercel і перезапустив деплой
- **THEN** інстанс працює як відкритий, а головна сторінка показує попередження про відкритий інстанс

## MODIFIED Requirements

### Requirement: Розгортання кнопкою Deploy to Vercel
README репозиторію SHALL містити кнопку «Deploy to Vercel». Вона клонує репозиторій у новий Vercel-проєкт і під час створення пропонує підключити Supabase через Vercel Marketplace, щоб обов'язкові змінні підключення підставилися автоматично.

#### Scenario: Деплой з README
- **WHEN** користувач натискає «Deploy to Vercel» у README і проходить майстер Vercel з підключенням Supabase
- **THEN** Vercel створює проєкт з обов'язковими змінними підключення до Supabase, і з усіх змінних вручну треба ввести лише `INSTANCE_PASSWORD`

#### Scenario: Опційні змінні задокументовано
- **WHEN** користувач читає README
- **THEN** README має розділ про `INSTANCE_PASSWORD` (навіщо він, рекомендована довжина, де змінити) і позначає її як обов'язкову при деплої кнопкою, а опційні `DEFAULT_LOCALE` і `RESULTS_RETENTION_DAYS` перелічує з дефолтами й описом, де їх задати у Vercel
