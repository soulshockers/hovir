# Proposal

## Why

Розширюваність — ключова ідея продукту: типи слайдів реалізовано як плагіни з єдиним контрактом. Редактор (`add-presentation-editor`), live-сесії (`add-live-sessions`) і всі плагіни (`static`, `poll`, `bulls-and-cows`, `quiz`, …) спираються на цей контракт, тож його треба закласти до них. Це пункт P0 дорожньої карти MVP: «Контракт плагінів + реєстр + тест-хелпер безпеки». Каркас (`bootstrap-platform`) уже створив порожній реєстр `plugins/index.ts`.

## What Changes

- Розміщення: кожен плагін — папка `plugins/<id>/` у монорепо; реєстрація в одному файлі `plugins/index.ts` (масив плагінів). Новий тип слайда додається через PR в основний репозиторій або у власний форк.
- TypeScript-контракт `SlidePlugin<Config, State, PublicState, PlayerView, Action>` з допоміжними типами `Actor`, `ActionResult`, `ServerCtx` (повний текст — `design.md`). Контракт проєктується так, щоб згодом плагіни можна було винести в npm-пакети без зміни інтерфейсу.
- Реєстр і пошук плагіна за `id`, валідація конфігу zod-схемою плагіна, міграція конфігу за `version` через `migrateConfig`.
- Правила для авторів плагінів як вимоги ядра: `handleAction` — чиста детермінована функція; секрети лише в `State`; лінива модель таймерів (`endsAt` + `tick`); throttling трансляцій `PublicState` не частіше ніж раз на ~500 мс на сесію.
- Тест-хелпер безпеки ядра, який для кожного зареєстрованого плагіна перевіряє, що `toPublic`/`toPlayer` не повертають секретів до завершення раунду.
- Вимога unit-тестів логіки для кожного плагіна (Vitest).

## Поза обсягом

- Конкретні плагіни (`static`, `poll` — `add-static-and-poll-slides`; `bulls-and-cows` — `add-bulls-and-cows`; інші — відповідні зміни).
- HTTP API дій і стану, канал `session:<id>`, таблиця `slide_states` (`add-live-sessions`); тут описано лише, як ядро викликає плагін.
- Генерація форми редактора з `configSchema` (`add-presentation-editor`).
- Плагіни як окремі npm-пакети, каталог плагінів (подальші етапи).
- `exportRows` для CSV (`add-session-history-and-export`); тут лише поле контракту.

## Capabilities

### New Capabilities
- `slide-plugin-contract`: розміщення й реєстрація плагінів, контракт `SlidePlugin`, валідація й міграція конфігу, правила для авторів (чистота, секрети), тест-хелпер безпеки, unit-тести плагінів.
- `slide-plugin-runtime`: як ядро виконує плагіни в сесії: ініціалізація стану, обробка дій, лінивий `tick` за таймером, throttling трансляцій, очки.

## Impact

- **Код:** `src/lib/plugins/` (типи контракту, реєстр-хелпери, рантайм-обгортки, throttling), `src/lib/plugins/testing/` (тест-хелпер безпеки), `plugins/index.ts` (типізований масив `SlidePlugin`), `plugins/README.md` (інструкція для авторів).
- **Тести:** Vitest для тест-хелпера на фікстурному плагіні; хелпер автоматично проганяється для кожного плагіна з реєстру.
- **БД / API:** без змін у цій зміні.
