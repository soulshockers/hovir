# Design

## Context

Каркас `bootstrap-platform` уже дає Drizzle-міграції в білді, схему «закрито за замовчуванням» (кожна таблиця в `public` з RLS, без грантів для `anon`/`authenticated`), ліниву zod-валідацію env і опційну змінну `INSTANCE_PASSWORD` (`openspec/specs/runtime-config/spec.md`). Мотивацію див. `proposal.md` (Why).

### Ролі

| Роль | Як отримує доступ | Можливості |
|---|---|---|
| **Власник інстансу** | Задає `INSTANCE_PASSWORD` в env під час деплою (опційно) | Майстер-доступ: список усіх презентацій, відновлення edit/present-посилань, видалення |
| **Автор / редактор** | Секретне **edit-посилання** `/e/<editToken>` | Редагування слайдів і налаштувань, перегляд історії сесій і результатів, експорт CSV, перевипуск посилань |
| **Доповідач** | Секретне **present-посилання** `/p/<presentToken>` | Старт/завершення сесії, перемикання слайдів, керування раундами (старт/стоп), модерація (приховати запис, видалити учасника) |
| **Слухач** | Публічний код сесії / QR → `/<code>` або `/join` | Участь в інтерактивах під автогенерованим ніком |

Ця зміна реалізує доступ власника, редактора (лише перевипуск посилань; редагування — `add-presentation-editor`, історія й CSV — `add-session-history-and-export`) і доповідача (лише вхід; сесії — `add-live-sessions`). Слухачі — `add-live-sessions`.

### Авторизація та доступ

- **Акаунтів немає.** Доступ до презентації дають два секретні посилання з випадковими токенами (≥128 біт ентропії). У БД зберігаються лише хеші токенів (SHA-256).
- **Створення презентацій:** якщо `INSTANCE_PASSWORD` задано, для створення потрібен пароль; якщо не задано, створювати може будь-хто. В UI показується попередження, що інстанс відкритий.
- **«Мої презентації»:** список edit/present-посилань зберігається в `localStorage` браузера автора. Після створення UI наполегливо пропонує скопіювати посилання або завантажити їх файлом (`.txt`). Відомий мінус: на іншому пристрої/браузері посилань немає, доки автор не перенесе їх сам.
- **Відновлення:** власник інстансу (через `INSTANCE_PASSWORD`) може переглянути всі презентації та перевипустити посилання.
- **Перевипуск посилань:** редактор може інвалідувати й перегенерувати present- або edit-токен (якщо посилання «втекло»).

### Флоу створення

1. На головній сторінці «Створити презентацію» (з паролем, якщо він заданий) → сервер створює презентацію і повертає edit- і present-посилання.
2. Показується модалка з обома посиланнями (копіювати / завантажити), і вони додаються в «Мої презентації» (`localStorage`).

### Маршрути («Публікація»)

Один інстанс — це один Vercel-проєкт. Презентації доступні як маршрути цього проєкту:
- `/e/<editToken>` — редактор;
- `/p/<presentToken>` — показ;
- `/<code>` і `/join` — вхід слухачів;
- `/admin` — майстер-доступ за `INSTANCE_PASSWORD`.

«Опублікувати» = розгорнути інстанс кнопкою. Власний домен налаштовується стандартно через Vercel. Окремих Vercel-проєктів на кожну презентацію немає.

### Env

| Змінна | Обов'язкова | Опис |
|---|---|---|
| `INSTANCE_PASSWORD` | ні | Пароль на створення презентацій + майстер-доступ |

## Goals / Non-Goals

**Goals:** модель доступу, на яку без змін спираються редактор, показ і сесії; жодного сирого токена чи IP у БД.

**Non-Goals:** акаунти, OAuth, magic link; синхронізація «Моїх презентацій» між пристроями (подальші етапи).

## Decisions

### Таблиця `presentations`

```
presentations
  id               uuid pk
  title            text
  theme            jsonb        -- { preset: 'light'|'dark'|'bright', accent, logoUrl }
  locale           text         -- мова інтерфейсу слухачів (uk|en|auto)
  edit_token_hash  text unique
  present_token_hash text unique
  created_at, updated_at timestamptz
```

`theme` і `locale` створюються з дефолтами (`{ preset: 'light' }`, `auto`); редагують і застосовують їх `add-presentation-editor`, `add-themes-and-presenter-controls`, `add-i18n`. Таблиця з `.enableRLS()`, без грантів для `anon`/`authenticated`. Видалення презентації каскадно видаляє її слайди й сесії (FK з `on delete cascade` у наступних змінах).

### Токени

256 біт із `crypto.getRandomValues`, base64url (43 символи). Хеш — SHA-256 у hex; пошук за унікальним індексом хешу. Формат перевіряється регулярним виразом до звернення до БД, тож некоректний токен не породжує запиту. Перевипуск — один `UPDATE … WHERE <hash> = $old RETURNING`, що робить заміну атомарною й дає 404 програшному з двох одночасних запитів.

Альтернатива — bcrypt/argon2 для хешів: зайве, бо токени мають повну ентропію, а повільний хеш лише сповільнив би кожен запит.

### Пароль інстансу і сесія `/admin`

Порівняння пароля — у сталий час (порівняння HMAC-дайджестів однакової довжини). Cookie сесії `/admin` — підписане значення `exp` + HMAC, де ключ виводиться з `INSTANCE_PASSWORD`; тому нових env-змінних не потрібно, а зміна пароля автоматично інвалідовує всі сесії. Строк — 12 годин, `HttpOnly`, `SameSite=Strict`, `Secure` на HTTPS. Мутації `/admin` додатково перевіряють `Origin`.

### Rate limiting

Таблиця `rate_limits` (ключ клієнта, бакет, лічильник/мітки, `expires_at`) у Postgres, атомарний інкремент через `INSERT … ON CONFLICT … DO UPDATE … RETURNING`. Ключ клієнта — HMAC IP-адреси (від платформи хостингу) із серверним секретом, виведеним із `SUPABASE_SERVICE_ROLE_KEY`, тож IP у БД не потрапляє. Застарілі записи видаляються ліниво під час наступних звернень. Альтернатива — Upstash/Vercel KV: суперечить zero-config і додала б інтеграцію.

### Гігієна секретних маршрутів

`headers()` у `next.config.ts` для `/e/:path*`, `/p/:path*`, `/admin/:path*`, `/api/presentations/:path*`, `/api/admin/:path*`: `Referrer-Policy: no-referrer`, `X-Robots-Tag: noindex, nofollow`, `Cache-Control: private, no-store`. Токени в API — лише в `Authorization` або тілі запиту.

## Risks / Trade-offs

- [Автор втратив посилання і `INSTANCE_PASSWORD` не задано] → відновити неможливо; модалка й `.txt` наполегливо пропонують зберегти посилання, а попередження про відкритий інстанс рекомендує задати пароль.
- [IP за NAT (аудиторія в одній мережі закладу) ділить ліміти] → ліміти створення й пароля стосуються лише авторів/власника, не слухачів; значення підібрано з запасом.
- [Відновлення власником інвалідовує обидва посилання автора] → UI попереджає й чекає підтвердження.

## Migration Plan

Нова expand-only міграція drizzle-kit (`presentations`, `rate_limits`), застосовується в білді. Відкат — Instant Rollback у Vercel; таблиці лишаються й не заважають попередній версії.
