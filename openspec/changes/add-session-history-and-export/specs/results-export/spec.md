# Spec Delta

## Purpose

Дає автору забрати результати сесії у вигляді CSV-файлів з edit-посилання: по сесії та по окремому слайду.

## ADDED Requirements

### Requirement: Експорт CSV по сесії
З edit-посилання SHALL бути доступний експорт CSV по сесії: учасники та очки (нік, сума очок, місце в лідерборді сесії, очки по кожному ігровому слайду). Файл MUST бути в UTF-8 з BOM (щоб коректно відкривався в табличних редакторах) і мати заголовок колонок.

#### Scenario: Експорт сесії
- **WHEN** редактор натискає «Експорт CSV» для завершеної сесії зі 40 учасниками
- **THEN** завантажується CSV з 40 рядками учасників (нік, очки, місце) і рядком заголовків

### Requirement: Експорт CSV по слайду
З edit-посилання SHALL бути доступний експорт CSV по окремому слайду сесії: рядки формує `plugin.exportRows` (опційний метод контракту). Якщо плагін не реалізує `exportRows`, експорт цього слайда MUST бути недоступним в UI.

#### Scenario: Слайд з exportRows
- **WHEN** редактор експортує слайд опитування
- **THEN** CSV містить рядки, які повернув `exportRows` для стану цього слайда

#### Scenario: Плагін без exportRows
- **WHEN** слайд має тип `static`
- **THEN** кнопки експорту для нього немає

### Requirement: Доступ і безпека експорту
Експорт SHALL вимагати чинного edit-токена в заголовку `Authorization` (не в query-рядку); інакше відповідь — 404. Значення комірок, що починаються з `=`, `+`, `-`, `@`, MUST екрануватися від CSV-ін'єкцій. Експорт MUST NOT містити секретів поза завершеними раундами, токенів чи IP.

#### Scenario: Без токена
- **WHEN** запит на експорт надходить без edit-токена
- **THEN** система повертає 404

#### Scenario: Формула в ніку чи відповіді
- **WHEN** текстова відповідь учасника починається з `=`
- **THEN** у CSV вона записана так, що табличний редактор не виконує її як формулу
