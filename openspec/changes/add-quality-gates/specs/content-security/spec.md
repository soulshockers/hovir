# Spec Delta

## Purpose

Захищає доповідачів і слухачів від шкідливого вмісту в браузері: CSP-заголовки, Markdown без сирого HTML і сувора валідація всіх вхідних даних.

## ADDED Requirements

### Requirement: CSP-заголовки
Усі сторінки інстансу SHALL віддаватися із заголовком `Content-Security-Policy`, що дозволяє скрипти лише з власного походження (без `unsafe-eval`; inline-скрипти лише з nonce), з'єднання лише з власним походженням і Supabase-проєктом інстансу (HTTPS і WSS для Realtime), зображення — з власного походження, `data:` і Supabase Storage, і забороняє вбудовування сторінок у чужі фрейми (`frame-ancestors 'none'`).

#### Scenario: Заголовок на сторінці слухача
- **WHEN** браузер завантажує `/<code>`
- **THEN** відповідь містить `Content-Security-Policy` з `frame-ancestors 'none'` і без `unsafe-eval`

#### Scenario: Сторонній скрипт
- **WHEN** на сторінку якимось чином потрапив `<script src="https://evil.example/x.js">`
- **THEN** браузер блокує його завантаження згідно з CSP

#### Scenario: Realtime працює
- **WHEN** клієнт підписується на канал Supabase Realtime під CSP
- **THEN** WebSocket-з'єднання до Supabase-проєкту інстансу дозволене

### Requirement: Markdown без сирого HTML
Markdown (текст статичних слайдів та інший вміст авторів) SHALL рендеритися без сирого HTML: HTML-теги в джерелі показуються як текст або відкидаються, а посилання з небезпечними схемами (`javascript:`, `data:`) MUST NOT ставати клікабельними.

#### Scenario: Тег script у тексті
- **WHEN** автор вводить у текст слайда `<script>alert(1)</script>`
- **THEN** скрипт не виконується, а на слайді немає HTML-елемента `script`

#### Scenario: Небезпечне посилання
- **WHEN** автор додає Markdown-посилання `[x](javascript:alert(1))`
- **THEN** на слайді воно не є клікабельним посиланням з цією адресою

### Requirement: Валідація всіх вхідних даних
Кожен API route SHALL валідувати тіло, параметри й заголовки запиту через zod до будь-якої обробки; невалідний запит MUST відхилятися з 400 і машинним кодом помилки без стек-трейсів.

#### Scenario: Невалідне тіло
- **WHEN** клієнт надсилає дію з полем неправильного типу
- **THEN** API повертає 400 з кодом помилки валідації, і стан не змінюється
