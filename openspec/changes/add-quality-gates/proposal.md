# Proposal

## Why

Платформа обіцяє роботу до 100 учасників на безкоштовних тарифах і серверну ігрову логіку, якій можна довіряти. Без автоматичних перевірок ці обіцянки не підтверджені: ліміти Supabase Free (~200 одночасних Realtime-з'єднань, обмеження на повідомлення) можна перевищити непомітно, а помилка в підрахунку биків/корів чи рейтингу зіпсує гру на сцені. Крім того, вміст слайдів (Markdown) і відповіді слухачів — недовірений ввід, що потребує захисту в браузері. Це розділ «Якість» дорожньої карти MVP разом з вимогами безпеки «CSP-заголовки» і «Markdown рендериться без сирого HTML».

## What Changes

- Unit-тести логіки всіх плагінів (Vitest), особливо підрахунок биків/корів і рейтинг, — обов'язковий гейт.
- E2E Playwright: доповідач + 3–5 слухачів проходять повний сценарій (створення презентації → редактор → старт сесії → вхід слухачів → опитування → «Бики та корови» → лідерборд → завершення).
- Навантажувальний скрипт: 100 віртуальних слухачів на одній сесії; перевіряє ліміти безкоштовних тарифів і затримки (scoreboard ≤ 1 с; відповідь на спробу/голос ≤ 500 мс p95).
- CSP-заголовки (Content-Security-Policy) на всіх сторінках.
- Markdown рендериться без сирого HTML.
- Валідація всіх вхідних даних API через zod (перевіряється тестами).

## Поза обсягом

- CI-пайплайн на конкретному сервісі (GitHub Actions тощо) — команди запускаються локально або в будь-якому CI.
- Навантажувальні тести понад 100 учасників і тести на платних тарифах.
- Аудит безпеки третьою стороною.

## Capabilities

### New Capabilities
- `content-security`: CSP-заголовки, безпечний рендер Markdown без сирого HTML, валідація всіх вхідних даних через zod.
- `quality-assurance`: unit-тести логіки плагінів, E2E-сценарій доповідач + слухачі, навантажувальний скрипт на 100 слухачів з цільовими затримками.
