# Proposal

## Why

Репозиторій поки містить лише `SPEC.md`. Усі наступні зміни MVP (доступ/токени, контракт плагінів, редактор, сесії) потребують спільного каркаса. Це перший пункт P0 у SPEC.md розділ 8: «Деплой кнопкою на Vercel + Supabase, автоміграції, README з інструкцією». Каркас має одразу відповідати принципу zero-config (SPEC.md 1, 3.1) і бути безкоштовним (SPEC.md 9). Ще він має закрити практичний ризик з відкритого питання 1 (SPEC.md 10): безкоштовний проєкт Supabase «засинає» після 7 днів неактивності, і власник інстансу повинен бачити це й знати, що робити.

## What Changes

- Next.js (App Router) + TypeScript + Tailwind CSS, менеджер пакетів pnpm. Один пакет у корені репозиторію з папкою `plugins/`: порожній реєстр `plugins/index.ts`, без жодного плагіна (SPEC.md 5.1, 6.1).
- Підключення до Supabase: серверний клієнт (service role, лише на сервері) і браузерний клієнт (anon key), а також пряме Postgres-підключення для міграцій і серверних запитів.
- Drizzle ORM + SQL-міграції, які генерує drizzle-kit і застосовує власний скрипт під час білда на Vercel. Вибір обґрунтовано в `design.md`.
- Базова схема БД лише для каркаса: службова таблиця `instance_meta`, закрита від `anon`/`authenticated`, і базові привілеї «закрито за замовчуванням» для схеми `public` (SPEC.md 7, RLS).
- Валідація env-змінних через zod: окремі серверна та клієнтська схеми, змінні з SPEC.md 6.5. Опційні змінні мають дефолти, а функції, які від них залежать, сюди не входять.
- Сторінка стану `/health` і JSON-ендпоінт `/api/health`. Вони показують стан конфігурації, підключення до Postgres/Supabase API і стан міграцій, а також окремо розпізнають «проєкт Supabase недоступний (ймовірно, призупинений)» і дають інструкцію з відновлення. На головній сторінці-заглушці є банер, якщо інстанс несправний.
- Vitest (unit) і Playwright (e2e) з одним smoke-тестом кожен. Обидва проходять без живого Supabase.
- Кнопка «Deploy to Vercel» з підключенням Supabase через Vercel Marketplace, `.env.example`, README з інструкцією з деплою та локальної розробки.

Поза обсягом (окремі зміни): edit/present-токени, `INSTANCE_PASSWORD` і `/admin`, таблиці домену з SPEC.md 7 (`presentations`, `slides`, `sessions` тощо), контракт плагінів і самі плагіни, редактор, live-сесії, Realtime-канали, Storage-bucket, i18n, CSP-заголовки, CI-пайплайн, Vercel Cron.

## Capabilities

### New Capabilities
- `instance-deployment`: розгортання інстансу кнопкою на Vercel + Supabase і автоматичне застосування міграцій БД під час деплою, разом з базовою схемою «закрито за замовчуванням».
- `runtime-config`: опис і валідація env-змінних інстансу (обов'язкові та опційні з дефолтами), поділ на серверні й публічні, безпечна поведінка при неповній конфігурації.
- `instance-health`: діагностика стану інстансу (конфігурація, БД, Supabase API, міграції) з розпізнаванням призупиненого Supabase Free і інструкціями для власника.

## Impact

- **Код:** новий застосунок у корені репозиторію (`src/app`, `src/lib/{env,db,supabase,health}`, `drizzle/`, `scripts/migrate.ts`, `plugins/`, `tests/`, `e2e/`).
- **Залежності:** `next`, `react`, `typescript`, `tailwindcss`, `zod`, `@supabase/supabase-js`, `drizzle-orm`, `drizzle-kit`, `postgres`, `server-only`, `tsx`, `vitest`, `@playwright/test`.
- **Інфраструктура:** білд на Vercel виконує міграції в Supabase Postgres. Скрипт `build` у `package.json` стає `migrate && next build`.
- **API:** новий публічний `GET /api/health`. Він повертає лише узагальнені статуси, без деталей помилок і секретів.
- **Документація:** README з кнопкою деплою, переліком env-змінних і розділом про «сплячий» Supabase Free.
