# slide-media Specification

## Purpose

Зберігання зображень слайдів і логотипів презентацій у Supabase Storage інстансу: завантаження з редактора за edit-посиланням і читання під час показу.

## Requirements

### Requirement: Bucket створюється міграцією
Bucket Supabase Storage для зображень слайдів і логотипів SHALL створюватися автоматично міграціями під час деплою, ідемпотентно, з лімітами розміру й типів файлів на рівні bucket. Власник інстансу MUST NOT створювати його вручну. На Postgres без схеми `storage` (локальна розробка) міграція MUST проходити без помилок.

#### Scenario: Перший деплой
- **WHEN** інстанс розгорнуто на порожньому Supabase-проєкті
- **THEN** bucket для медіа існує, і завантаження зображень у редакторі працює

#### Scenario: Повторний деплой
- **WHEN** міграції застосовуються вдруге
- **THEN** bucket лишається один, із тими самими налаштуваннями

### Requirement: Завантаження за edit-токеном
Завантажувати зображення SHALL лише через серверний API з чинним edit-токеном презентації. Прямий запис, зміна, видалення й перелік файлів у Storage з anon-ключем MUST бути заборонені.

#### Scenario: Завантаження зображення
- **WHEN** автор додає зображення до слайда в редакторі
- **THEN** файл зберігається в Storage, а поле конфігу отримує URL зображення

#### Scenario: Запис з anon-ключем
- **WHEN** клієнт намагається записати файл у bucket напряму з anon-ключем
- **THEN** Storage відхиляє запис

#### Scenario: Невалідний токен
- **WHEN** запит завантаження надходить з present-токеном або відкликаним edit-токеном
- **THEN** API повертає 404, і файл не збережено

### Requirement: Обмеження файлів
Сервер SHALL приймати лише растрові зображення (PNG, JPEG, WebP, GIF) розміром до 4 МБ. Тип MUST визначатися за вмістом файлу (сигнатурою), а не за розширенням чи заголовком клієнта. Завеликий файл MUST відхилятися з кодом 413, інший тип (зокрема SVG) — з кодом 415; UI показує зрозуміле повідомлення.

#### Scenario: Завеликий файл
- **WHEN** автор завантажує зображення 8 МБ
- **THEN** сервер відхиляє файл, а редактор повідомляє про ліміт 4 МБ

#### Scenario: SVG
- **WHEN** автор завантажує `.svg`
- **THEN** сервер відхиляє файл як непідтримуваний тип

#### Scenario: Підроблене розширення
- **WHEN** автор завантажує HTML-файл, перейменований на `.png`
- **THEN** сервер відхиляє файл як непідтримуваний тип

### Requirement: Лише власні зображення в конфігах
Сервер SHALL приймати в полях-зображеннях конфігу слайда й у логотипі теми лише URL файлів цієї презентації в bucket інстансу (або порожнє значення). Сторонні URL MUST відхилятися з помилкою валідації, щоб пристрої слухачів не звертались до сторонніх серверів.

#### Scenario: Стороннє зображення
- **WHEN** запит зберігає конфіг слайда з URL зображення на сторонньому домені
- **THEN** сервер відхиляє конфіг з помилкою валідації

#### Scenario: Зображення іншої презентації
- **WHEN** конфіг містить URL файлу з папки іншої презентації
- **THEN** сервер відхиляє конфіг з помилкою валідації

### Requirement: Читання для показу
Завантажені зображення SHALL бути доступні на читання екранам доповідача й слухачів без токенів, за непрогнозованими URL (шлях з UUID). Видалення презентації MUST видаляти її файли.

#### Scenario: Читання без токенів
- **WHEN** браузер без жодного токена запитує публічний URL завантаженого зображення
- **THEN** отримує зображення з його типом (`image/png` тощо)

#### Scenario: Видалення презентації
- **WHEN** власник інстансу видаляє презентацію
- **THEN** її зображення видаляються зі Storage
