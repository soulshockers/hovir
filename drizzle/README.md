# Міграції БД

SQL-міграції генерує drizzle-kit зі схеми `src/lib/db/schema/`. Застосовує їх `scripts/migrate.ts` під час кожного білда на Vercel (`pnpm build`) або вручну (`pnpm db:migrate`).

- Зміна схеми: відредагуйте `src/lib/db/schema/*` → `pnpm db:generate --name <назва>` → перегляньте SQL → закомітьте.
- SQL без TS-відповідника (гранти, RLS-політики, Storage, Realtime): `pnpm db:generate --custom --name <назва>`, потім заповніть порожній файл.

## Правила

1. **Лише expand-only.** Preview-деплої застосовують міграції до тієї самої БД, що й production, тож попередня версія коду має працювати з новою схемою. Перейменування чи видалення колонок і таблиць робіть у два релізи: спершу додайте нове, а прибирайте старе в наступному.
2. **Кожна нова таблиця в `public` — з `.enableRLS()`** у Drizzle-схемі. Ролі `anon`/`authenticated` доступу не мають (див. `0001_closed_by_default.sql`); дані читає й пише лише серверний код.
3. Не редагуйте вже застосовані міграції: виправлення робиться новою міграцією.
